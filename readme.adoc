= tung

tung is a small functional programming tongue with

* type inference, algebraic data,
* closed records,
* type classes,
* algebraic effects,
* and infix notation.

== install

install the command and vscode extension.

[source,sh]
----
brew bundle
make install
----

the command is installed at `~/.local/bin/tung` by default.
set `PREFIX` or `BIN_DIR` to choose another destination.

== run

[cols="1,1",options="header"]
|===
| command
| purpose

| `tung program.tung [arguments...]`
| runneþ `main` with the remaining arguments

| `tung --check program.tung`
| checkeþ a program with `main`

| `tung --check-module module.tung`
| checkeþ a program without `main`

| `tung --type-of name program.tung`
| printeþ the inferred type of a name

| `tung --format file.tung [more.tung...]`
| formateþ files in stead

|===

`main` takeþ `𝟙`, yieldeþ `𝟙`, and may use the standard runtime effects.

[source,tung]
----
bring ground.tung

let (_: 𝟙) main: 𝟙 ! console =
  'hello, tung' write-line
----

examples are in link:byspel/[`byspel/`].

== syntax

tung useþ function-second syntax for application.
`$` groupeþ the expression on its left before passing it to the function on its right.

[source,tung]
----
a f           # f a in haskell
a f b c       # f a b c in haskell
a f $ g b     # g (f a) b in haskell
<(f, a, b, c) # (a f b) f c
>(f, a, b, c) # a f (b f c)
----

the opening parenthesis must touch `r`, `<`, or `>` in these special forms.
an associative form requireþ its combining function and at least two values.

functions are curried.
effects follow `!` on a function arrow, and
`(term: type)` constraineþ any term.

closed record types use `r(field: type)`, and values use `r(field = value)`;
`r(= record, field = value)` updateþ a record, and `r(= record, - field)` removeþ a field.

== keywords

[cols="1,6",options="header"]
|===
| keyword
| use

| `let`
| bindeþ a value to a name

| `graiþ`
| requireþ shape evidence from the caller

| `show`
| publisheþ a declaration or re-publisheþ a visible term

| `show-ilk`
| publisheþ a type, effect, or shape name

| `bring`
| importeþ a module

| `let-ilk`
| defineþ a type alias

| `kin`
| declareþ an algebraic data type and its constructors

| `deed`
| declareþ an algebraic effect and its operations

| `yield`
| return a block result or handleþ a normal `try` result

| `fremmed`
| bindeþ an annotated file-level `let` to the host function named by a text key

| `shape`
| declareþ a statically selected interface, requirements, and laws

| `fill`
| provideþ evidence and implementations for a shape

| `law`
| recordeþ a type-checked equation without proving it

| `match`
| selecteþ an exhaustive, non-redundant pattern case

| `try`
| handleþ effects performed by an expression

| `eftgin`
| continueþ the captured computation inside an operation case
|===

`bring` introduceþ a module with the file name or an optional name given.

[source,tung]
----
bring data/list.tung
bring data/table.tung hashmap

let my-empty-list = list@empty
let my-empty-table = hashmap@empty
----

imported names may stay bare when unambiguous.
declarations remain private unless published with `show` or `show-ilk`. module lookup searcheþ local files,
`TUNG_PATH`, then the embedded standard bookhoard.

handlers are deep, and thou mayst call `eftgin` more than once.
partial application is pure; an effect operation runneþ only when fully applied.

[source,tung]
----
bring ground.tung

deed ask {
  integer ask: integer
}

let answer: text = try 10 ask {
  yield n | n to-text,
  n ask | (n + 1) eftgin
}
----

evaluation is strict and call-by-value.
checking precedeþ evaluation, and file-level initialisation must stay pure.
