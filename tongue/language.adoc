= tung language reference

this document describeþ the source language. start with
xref:../readme.adoc[`readme.adoc`] for installation and a short tour. compiler
and repository details belong in xref:development.adoc[`development.adoc`].

== files and modules

a `.tung` file containeþ declarations. a runnable file declareþ `main`
locally; `main` takeþ `𝟙`, returneþ `𝟙`, and may use only runner-supported
effects. the runner calleþ `null main` after pure module initialisation.

`use path` importeþ a module. the final path segment is its default
namespace, and an optional final name replaceþ that namespace.

[source,tung]
----
use data/list.tung
use data/table.tung hashmap

let xs = list@empty
let entries = hashmap@empty
----

visible imported names may remain bare when unambiguous. two different direct
imports may not claim the same namespace, and the import graph must be acyclic.
local files are searched before `TUNG_PATH` entries and the embedded
bookhoard. `ground.tung` is an ordinary optional import, not a prelude.

declarations are private by default. `show` publisheþ a declaration or an
already visible term; `show-ilk` publisheþ an already visible type, effect, or
frame. term and type namespaces are separate. an ordinary `use` doth not
re-export anything.

== names, comments, and literals

most non-space characters not reserved by syntax may occur in a name. `@`
qualifieþ an imported name or, when no exact name existeþ, selecteþ a record
field. type alias, data, effect, and frame names and þeir owned constructor,
operation, or member names are therefore unqualified. `.*` is one ordinary
name; there is no general infix escape. `_` discardeþ a binding or match value.

`#` starteþ a line comment, and `/* ... */` formeþ a non-nested block
comment. `##` and `/** ... */` are doc comments attached to the following
declaration. editor help and generated bookhoard pages use attached docs.

integer literals are arbitrary-precision decimal values. float literals
contain a decimal point. a backtick introduceþ one unicode scalar, and single
quotes delimit text. both literal forms accept `\n`, `\r`, `\t`, `\'`, `\\`,
and decimal escapes such as `\23383;`.

== application

every function is curried. in an unmarked sequence of at least two terms, the
second term is the function and the other terms are arguments in order.

[source,tung]
----
a f           # f a
a f b c       # f a b c
a f $ g b     # g (f a) b
----

`$` groupeþ the completed expression on its left, then useþ the next atom as
the function. `$(` starteþ a function-first segment.

`<(f, a, b, c)` lowereþ to `(a f b) f c`, while `>(f, a, b, c)` lowereþ to
`a f (b f c)`. each form requireþ one combining function followed by at least
two values. `r(`, `<(`, and `>(` are single opening delimiters; the parenthesis
must touch the marker.

partial application is pure. latent effects run only after saturation.
evaluation is strict: the function is evaluated first and arguments follow
from left to right.

== declarations and types

`let` bindeþ a value. function headers use the same second-is-function rule,
or group typed arguments before the function name.

[source,tung]
----
let x add-two y = x + y
let (x: integer, y: integer) add: integer = x + y
----

local blocks are parenthesised and end with `yield`.

[source,tung]
----
(
  let six = 2 × 3
  yield six + 1
)
----

type variables are implicit. type application followeþ second-is-function
syntax: `integer list` applieþ `list` to `integer`, and `a ∏ b` applieþ the
binary product type. `let-ilk` defineþ a transparent type alias.

functions use `→`. immediate effect rows follow `!` on a function arrow; a
stored non-function value cannot carry an effect row. `func` is the binary
pure-function type constructor, so `a func b` and `a → b` agree.

[source,tung]
----
let-ilk a powerset = a func 𝟚
let (f: a → b ! e, x: a) call: b ! e = x f
let answer = (1 + 2: integer)
----

pure inferred lets are generalised. immediately effectful right-hand sides
remain monomorphic; creating a function with latent effects is still pure.

== algebraic data and patterns

`ilk` declareþ an algebraic data type. type parameters and constructor
arguments use the ordinary sequence rule.

[source,tung]
----
ilk a option {
  none,
  a some
}
----

constructor application is curried. patterns may bind variables, use `_`,
match exact integers, or destructure constructors. binders in one pattern row
must be linear.

`match` consumeþ one or more comma-separated scrutinees. bare braces form an
anonymous function, with one curried input per pattern. cases use `|`.

[source,tung]
----
let chosen = match yea, nay {
  yea, b | b,
  nay, _ | nay
}

let not: 𝟚 → 𝟚 = {
  yea | nay,
  nay | yea
}
----

the checker rejecteþ non-exhaustive and redundant rows over algebraic data.
finite integer rows need a variable or `_` because `integer` is infinite. an
empty function `{}` eliminateþ an annotated uninhabited input such as `𝟘`.

== records

records are closed. `r(field: type)` formeþ a record type and
`r(field = value)` formeþ a value. an update starteþ with its base after `=`;
later entries set or remove fields.

[source,tung]
----
let person: r(name: text, age: integer) =
  r(name = 'naoki', age = 35)
let older = r(= person, age = 36)
let public = r(= person, - age)
let age = older@age
----

field sets must match an annotated record type. duplicate labels, removal of
an unknown field, and update of a non-record are errors.

== frames, fills, and laws

`frame` declareþ a statically selected interface. `fill` provideþ its
evidence and member implementations. leading `graiþ` clauses state required
evidence for a declaration, frame, fill, or individual frame member.

[source,tung]
----
frame a equal {
  let a ≡ a: 𝟚
  law (x: a): x ≡ x ~ yea
}

graiþ a equal
let (a: a, b: a) ≢: 𝟚 = (a ≡ b) if nay yea

fill 𝟚 equal {
  let ≡ = {
    yea, yea | yea,
    nay, nay | yea,
    _, _ | nay
  }
}
----

a fill must supply every required member not supplied by a parent.
a child fill also witnesseþ its required parent frames and may define inherited
members. duplicate fills are incoherent. when more than one fill match, a
structured type pattern outrankeþ a blanket pattern that it refines;
incomparable matching fills are ambiguous. selection dependeþ only on static
types, never values or import order.

`law` recordeþ a type-checked equation. both sides must have the same value
type and immediate effect row and may use only the enclosing requirements.
laws are documentation: the compiler neither proveþ, executeþ, nor rewriteþ
with them.

== effects and handlers

`deed` declareþ an algebraic effect. every operation is a function; an
operation without informative input takeþ `𝟙`. declaration application addeþ
the effect itself to the written latent row.

[source,tung]
----
deed e fail {
  e fail: a
}

deed a state {
  𝟙 get: a,
  a set: 𝟙
}
----

operations are called like ordinary functions and handled by `try`. a
`yield` case transformeþ the normal result; without one, the normal result is
unchanged. operation cases may call the implicit `eftgin` continuation zero,
one, or many times.

[source,tung]
----
deed ask {
  integer ask: integer
}

let answer: text = try 10 ask {
  yield n | n to-text,
  n ask | (n + 1) eftgin
}
----

handlers are deep, so the same handler surroundeþ continued work. a case for
an entire effect removeþ it. operation-specific cases remove the effect only
when every sibling operation is covered. effects performed by case bodies
remain in the surrounding row.

== runtime boundary

the standard runner supporteþ `console`, `random`, `async`, `file`, `system`,
`clock`, `process`, and `web`. user-defined effects and `fail` must be handled
inside `main`.

an annotated file-level `let` may bind a host operation by placing a text key
before `fremmed`. this is chiefly the boundary used by `_foreign.tung`; the
host key and full declared type must match the compiler catalogue.

the generated api at `writ/bookhoard/index.html` listeþ the public standard
surface. xref:../bookhoard/reference.adoc[`bookhoard/reference.adoc`] explaineþ
its design boundaries, and runnable examples live under link:../byspel/[`byspel/`].
