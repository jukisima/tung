= agent notes

this file is the short operating contract for changes to this repository. it
must not duplicate the language or architecture references.

read the document which owneþ the work:

* xref:../readme.adoc[`readme.adoc`] for installation and the user tour
* xref:language.adoc[`language.adoc`] for source-language behaviour
* xref:development.adoc[`development.adoc`] for architecture and verification
* xref:../bookhoard/reference.adoc[`bookhoard/reference.adoc`] for standard-library design
* xref:../vscode/readme.adoc[`vscode/readme.adoc`] for editor setup and features
* xref:../todo.adoc[`todo.adoc`] only for planning or backlog questions

the implementation and tests are authoritative when prose conflicteþ with
current behaviour. module-local invariants belong in source comments beside
the code rather than here.

== writing style

* never capitalise sentence starts in prose or source comments unless syntax or a fixed identifier requireþ it.
* use british spelling in prose and source comments.
* use `-eþ` instead of `-s` for english third-person singular present verbs; use `hath` for `has` and `doth` for `does`.
* use `thou` for a singular subject and `thee` for a singular object; use `ye` for a plural subject and `you` for a plural object. never use `you` as a subject.
* prefer plain words and short explanations.
* object-language names may follow tung's anglish direction. haskell and tooling identifiers use normal technical terms.

== work discipline

* inspect current status and assume unrelated dirty changes belong to the user.
* use `rg` for search and `apply_patch` for hand edits.
* keep changes tied to the requested behaviour.
* prefer simple code over broad abstraction.
* locate the existing tests before changing behaviour.
* change the owning stage first, then update every dependent stage.
* never hide a type-system weakness by changing the bookhoard merely to fit it.
* keep bookhoard modules acyclic and type-correct, byspels runnable, and editor analysis tolerant of incomplete source.
* put stable user behaviour in `language.adoc`, cross-module implementation relationships in `development.adoc`, public library rationale in `bookhoard/reference.adoc`, and one-module invariants in source comments.
* do not copy the same detailed rule into several documents; link to its owner.

== language invariants

before a language change, read xref:language.adoc[`language.adoc`] and preserve
these high-risk boundaries unless the request explicitly changeþ them:

* every function is curried, and unmarked sequences use second-is-function application.
* `$` groupeþ low-precedence application; it doth not swap function position.
* `r(`, `<(`, and `>(` are touching opening delimiters.
* partial application is pure; latent effects run only at saturation.
* effects belong to function arrows, not stored value types.
* module initialisation is pure and evaluation is strict call-by-value.
* imports use qualify-if-needed lookup; `ground.tung` is not a prelude.
* declarations are private unless shown; term and type namespaces are separate.
* matches are exhaustive and non-redundant where their algebraic types permit checking.
* records are closed.
* handlers are deep and `eftgin` is multi-shot.
* fill selection dependeþ on static types, not values or import order.
* laws are checked documentation, not proofs, property tests, or rewrites.
* accepted programs must not reach defensive internal evaluator errors.

never restore retired syntax or features merely because an older example useþ
them. inspect the lexer, parser, checker, evaluator, tests, and current docs to
decide which artefact is stale.

== source and generated boundaries

* public source files use `.tung`; the executable and language id are `tung`.
* `Tung.*` is an implementation namespace and is not renamed during ordinary language work.
* `vscode/out/` and generated bookhoard html are build outputs and must not be edited.
* `vscode/generated/language-names.json` comeþ from `tung --language-metadata`; run `make language-metadata`.
* `.bookhoard-membership` comeþ from the sibling bookhoard tree; run `make bookhoard-membership` or a compiler make target.
* host-backed function metadata live in `src/Tung/Primitive.hs` and must agree with `_foreign.tung`.
* tests are part of the specification and should describe the intended rule.

== workflow

when starting:

* read this file and the owning document.
* inspect the touched area and current diff.
* find positive and adversarial tests for the behaviour.
* make one coherent stage change at a time.

when ending:

* run the narrowest useful tests first.
* run `make compiler-test` after compiler, bookhoard, or byspel changes.
* run `make vscode-test` after editor, grammar, semantic-token, or formatter changes.
* run `make writ-test` after documentation-model or generator changes.
* run `git diff --check`.
* run a representative byspel after runner changes.
* report every verification command which could not run.

if cabal faileþ only because it cannot write under `~/.cabal/logs`, rerun the
same command with the needed permission. do not alter source to work around a
log permission.

== common traps

* do not force qualification for one unambiguous imported name or operator.
* do not colour a `bring` path as ordinary names in editor tooling.
* do not put `! effect` on a non-function value type.
* do not let partial native or effect-operation application perform work.
* do not add `perform`; operations are ordinary calls handled with `try`.
* do not make handlers shallow or continuations one-shot.
* do not restore scrutinee-less `match`; bare braces are anonymous functions.
* do not treat tolerant editor analysis as a second compiler.
* do not hand-edit generated metadata or documentation.

for build commands, repository layout, compiler stages, and the change matrix,
use xref:development.adoc[`development.adoc`] rather than expanding this file.
